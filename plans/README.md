Integrate one hybrid candidate/ranking/hydration owner behind these paths, preserving their scope/date/entity/source-kind contracts. Exact aggregates/status/date reads stay SQL; similarity results never imply complete coverage or establish a promise as fact.
- Lifecycle: index committed member sources, current interactions/memory and uploaded/generated document sections via the existing Queue/recovery owner, deduplicated by source revision/content hash. Preserve source type/author/date and label Otis-generated advice as generated content, not member fact. Corrections/Undo/forget/merges/retention/erasure must invalidate or replace affected entries. Source hydration rejects stale/inaccessible vectors before text can reach the model. Vectorize is a rebuildable index, never canonical memory.
- Candidate architecture for discussion: Gemini Embedding 2 text input at 768 dimensions plus Cloudflare Vectorize, shared keyword+semantic retrieval, bounded initial recall context, existing tools and background indexing. Keep preferences/recent conversation/current facts separate from relevance-ranked historical evidence. Initial recall retrieval, tool retrieval and document authoring reuse the same ranking/budget/source owner. Semantic result caches need source revision/access freshness; a cached query vector alone does not.

The observed roughly 0.8 s request cost makes an unconditional blocking embedding call on every message unjustified. Explore bounded/parallel retrieval and deterministic fast paths, keeping Stop/timeouts and keyword fallback on throttling. No automatic model switch, quota bypass, new LLM router or unrestricted tool execution.
- Compatibility check: pin one retrieval profile (`gemini-embedding-2`, 768 dimensions, cosine, chunk/prompt format version). Embedding 2 automatically normalizes reduced-dimension output and uses retrieval instruction prefixes rather than the legacy `taskType`: `task: search result | query: ...` for queries and `title: ... | text: ...` for passages. Validate vector length, finite values and nonzero norm before writing/querying. Multiple parts in one input produce one aggregated vector; require one returned vector per independent chunk. Do not mix Embedding 001 and Embedding 2 vectors or silently change profile on provider failure.
- Actual Cloudflare state: `pnpm exec wrangler vectorize list` succeeded on 2026-10-10 and reported no indexes in the configured account; no Vectorize binding is currently present in `wrangler.jsonc`. Gemini access is tested, but the Worker → Gemini → Vectorize → scoped D1/R2 source path is not yet tested. No remote index/resource was created.
- Index setup and freshness: use the trusted workspace as namespace, globally unique compact vector IDs including workspace/source/revision/chunk identity, and only needed metadata indexes created before the first upsert. Versioned IDs prevent late old jobs overwriting a newer source's vector; repeated jobs upsert the same revision ID. Index writes/deletes are asynchronous. Recheck the source's current revision and access during batched hydration, reject obsolete/forgotten content immediately, and retrieve recent not-yet-indexed sources through existing SQL/FTS. Persist pending indexing through existing durable Queue/recovery machinery so a commit-to-enqueue failure cannot silently lose a source. Clean old versions asynchronously; never await indexing visibility on Save or poll per message.
- Live acceptance before adoption: use an isolated synthetic corpus through a real Worker binding; verify the index dimension/metric, returned vector count/shape, namespace and indexed metadata filtering, relevant versus unrelated retrieval and original-source hydration. Account for asynchronous visibility with a bounded probe wait, not a runtime heartbeat. Exercise correction followed by a delayed old indexing job, Undo/forget/delete, duplicate delivery/restart and removed-member/other-workspace denial. Normal queries return IDs/scores and necessary indexed metadata, not raw vectors/full metadata; default Vectorize scoring is approximate, so do not require bit-identical scores to local cosine. Compare semantic+keyword recall and total answer latency on representative multilingual questions before enabling initial-context integration. Embedding/Vectorize timeout, 429 or outage must fall back to keyword retrieval with honest coverage.
