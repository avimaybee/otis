### Considered and rejected for this pass

- Replacing interactive turns with Cloudflare Workflows is not justified as a latency fix. Workers already supports [incremental response streaming](https://developers.cloudflare.com/workers/runtime-apis/streams/); [Workflows](https://developers.cloudflare.com/workflows/) supplies durable steps/retries/sleeps that overlap the existing execution owners. This is an architectural judgment, not a benchmark claiming Workflows is slower. Reconsider only for a concrete long-running job the existing Queue/actor cannot handle simply.
- A new CRM/dashboard, vector store, report engine or second model that formats tables does not address the observed failures. Existing sourced reads, client panes, Markdown tables and ledger commands can support the proposed experiences.
- Forced terse replies or a global smaller context window would undermine detailed requests and older-image/source recall. Remove irrelevant/repeated work; keep requested detail and honest source coverage.
- No proposals to rebuild already-present corrections, merging, cross-chat search, image retention, recurrence, failed-run Retry, note attribution or scoped access recovery. No private-note feature.
