## 1. What 008C implements

- **One scroll owner.** `Transcript.tsx` keeps `use-stick-to-bottom` as the sole follow/release/Jump owner (instant adjustments only, reduced motion honored by construction). No custom scrollHeight compensation, no scrollIntoView, no message-driven follow effects. Explicit send-triggered return only (`followSignal`, taken at the local send moment — never on delayed acceptance; R10), saved per-chat reading anchors (bounded module map, positions only), partitioned announcements (below). Render-side `followRef` assignment moved into an effect.
- **Stable prepend.** `applyOlderMessages`/`mergeMessages` dedupe by stable message identity and keep sequence order; `ConversationScreen.loadOlder` keeps its overlap guard, same-cursor in-place retry and generation/scope fencing, so streaming continues while a history request resolves and late other-chat responses are ignored.
- **One typed router.** New `apps/web/src/router.tsx` (`createRootRoute`/`createRoute`/`createRouter`/`RouterProvider`, TanStack React v1 APIs verified against the installed dist types): single `/` route with `validateSearch` preserving the exact `?workspace=<id>&chat=<id>` shape (`chat=new` for new chats). `ConversationScreen` is route-controlled (no internal selection state, no pushState/popstate); Back/Forward arrive as route props with overlay/draft resets, epoch plus explicit operation-target guards ignore late/stale responses (R10: stale old-route 403 cannot close the current chat), the stream detaches via the existing `readyChatId` effect cleanup. The operation fence mirror syncs in `navigate()` and the committed-selection effect, never during render. Dev entries (`ux-preview`, `review/Review`) render through the same router with memory history seeded from their URL.
- **Mobile drawer on Vaul, one shared dismissal owner.** `HistoryNav` drawer renders Vaul `Drawer.Root` (`modal`, `direction="left"`) with the approved drawer recipe, sr-only `Drawer.Title`, backdrop `otis-drawer-scrim` (background token at approved 80%, mirroring the dialog `::backdrop` recipe the checker pins), explicit initial focus on Close, deterministic return focus, body scroll lock and focus trap from the primitive. Dismissal/Back/marker ownership lives in the single shared `useOverlayHistory` hook used by both the drawer and the native `Overlay` dialogs — no parallel drawer implementations. The drawer stays mounted with controlled `open` so the graceful close lifecycle (focus return, exit) runs.
- **Overlay Back ownership.** Native `Overlay` dialogs keep showModal semantics and share the same `useOverlayHistory` hook: opening pushes one same-URL marker entry (no chat navigation entry), Back closes the top overlay without navigating, explicit Close/backdrop/Escape consumes the marker only when still on top. Marker consumption is deferred one microtask because TanStack history lands pushState on a microtask; a synchronous recheck would mistake a fresh navigation for the marker and rewind it (reproduced and fixed; see §6).
- **One viewport/composer owner.** `useViewportComposer` returns a callback ref tracking the mounted composer element (never a stable ref object, so read-only views, own-chat mounts and element replacements are all observed, with disconnect on replacement/unmount), observes visualViewport resize AND scroll (iOS shifts without resize; `interactive-widget` is Android-only) plus window resize, publishes measured `--app-viewport-height` and `--app-composer-height` variables only on change, removes both on cleanup. Viewport meta was already exact. No keyboard-open inference, no double safe-area subtraction.
- **Formatting owner.** New `apps/web/src/i18n/format.ts`: viewer locale + explicit display-timezone Intl helpers for clock times, day labels, zone-aware calendar-date keys (no UTC-substring comparison), money with actual units (RON via ro-RO, no invented currency), `''` for missing/invalid (never "Invalid Date"), validated ro/hu/en language tags. Wired into Transcript separators/timestamps and Detail/Source pane dates. Contract gap specified exactly (P2 in `plans/008C-contract-proposals.md`): no workspace display-timezone field exists (only member `brief_timezone` for brief schedules and per-deadline source-member zones, neither substituted); viewer zone applies until an additive contract lands.
- **Language.** App language follows the saved member reply language (validated ro/hu/en, default en) via a small effect where member settings load. No per-message language metadata exists on ChatMessage, so unknown content inherits the app language — including in mixed-language threads, which per-message `lang` cannot honestly distinguish today (specified exactly as P1 in `plans/008C-contract-proposals.md`); no detection service, no model call, no ambient inference, no contract invention. Diacritics render through the existing Inter latin-ext path.
- **Accessibility.** Stable `role="log"` always polite; token/working subtrees `aria-live="off"`; history partition: groups below the first-paint sequence floor carry `aria-live="off"` on their existing group element (layout-neutral attribute, no wrapper/restyle), so older pages never announce while completions in the live partition announce exactly once — including completions that settle while a prepend overlaps (the 800ms whole-log mute is removed because it swallowed those completions). Stable keys mean snapshot refetch adds no nodes; `aria-busy` clears on failure/completion; Thinking disclosure keeps one named trigger with correct expanded state; ChatOverflow Stop is now a menu action (`DropdownMenuItem`), not a radio option. Screen-reader once-only behavior itself remains in the explicitly unverified column (§5).
- **Bounded inspection.** DetailPane (action-scoped) and SourcePane (memory-scoped single read) stay the single-read owners with honest unavailable states. Entity-timeline stays contract-only: specified exactly as P3 in `plans/008C-contract-proposals.md` (endpoint, DTOs, authority, derivation flag); no timeline built, no workspace-wide fetch added.

## 6. Defects found and disposition

- **Delayed-ack scroll yank (reviewer-found production regression, fixed).** `deliverEntry` bumped `followSignal` after `await api.sendMessage`: a reader who scrolled up while the POST was in flight was dragged to the bottom on HTTP 202 (reviewer probe `delayed-ack-scroll`: scrollTop 200 → 10561/11264). Fix: the explicit send-triggered follow now happens once in `send()` at the local acceptance moment; delayed acceptance, retries and reconciled snapshots only reconcile and never force follow. Discriminating test holds the POST, scrolls to 200 via two descending scroll positions, resolves 202, and asserts the Jump control stays put. Retry takes no follow (the reader is already at the failed bubble). The reviewer `delayed-ack-scroll` probe should be re-run against this fix; I have no browser tool here.
- **Stale-route auth failure closes the current chat (fixed).** The `selectionKey` effect intentionally leaves `epoch` unchanged (self-created navigations re-anchor their own generation), so the `deliverEntry` catch — which gated only on epoch — ran `loseAccess()` for a stale old-route 403 after an external Back/Forward move (paused send on A → Back to B → A 403 destroyed B). Fix: the catch also fences by the operation's own route target (`targetChat`, tracked through new-chat creation); self-created navigation re-anchors generation and target together, so it stays live. Discriminating test uses a real `history.back()` and asserts B intact with no unavailable state; without the fence it renders 'Conversation unavailable'.
- **Stale-props render clobbering the operation mirror (fixed while fixing the above).** The render-body `selected.current = …` assignment let any stale-props render overwrite `navigate()`'s synchronous write, which first broke the R8 same-UUID retry test under the new target fence. Fix: the mirror updates only in `navigate()` and in the committed-selection effect, never during render. Accepted residual: a sub-paint window where an external move committed but the effect has not flushed yet reads the previous mirror — same class as the pre-existing epoch race, unobservable outside that window.
- **Overlay marker rewind race (fixed).** Closing the drawer to select a chat navigated correctly by URL but the router never committed: the unmount cleanup read raw `history.state` synchronously while TanStack's pushState was still queued on a microtask, saw its own marker on top, and called `history.back()`, rewinding the fresh navigation (proven with load/notify instrumentation; `latestLocation` never advanced). Fix: defer the top-marker recheck one microtask. Deterministic regression test: drawer select navigates once and closes.
- **Drawer visual layering regression R11 (reviewer probe, fixed).** Native Chrome at 390px with the drawer open: the conversation topbar (`position: relative; z-index: 5`) painted over the drawer and scrim, because the Vaul portal Content/Overlay carried no layer above it (the native dialog had lived in the top layer). Fix: narrow shared overlay layer — `z-index: 10` (the existing `.otis-overlay` value, no new token) on both `.otis-drawer-scrim` and `.otis-drawer`, separated by DOM order. Same probe also showed the drawer box twice at identical geometry: `Drawer.Content` and the inner `nav` both carried `otis-drawer` (absolute inset, duplicated panels/padding). Fix: one surface/position owner — Content keeps `otis-drawer`, the inner nav is normal flow (`otis-drawer__nav`: flex column only, no panel values). The `nav/drawer` Storybook story now renders open for rendered-story/probe evidence; reviewer to re-run `drawer-review.mjs`. Tested Back behavior preserved (one dialog, Close focused, Back closes + returns focus, same chat URL).
- **pnpm layout confusion (environment, no source impact).** `@tanstack/history`/`router-core`/`react-store` resolve only through `react-router`'s store links; direct bare imports fail by design (pnpm strictness). Briefly investigated dual `.pnpm` stores and stale-looking 4-up symlinks; all links resolve into the single `Otis/node_modules/.pnpm` store (scope-nested links need one extra `..`). No package.json/lockfile change resulted. `router ok / createRouter + createMemoryHistory are functions` verified before implementing.
