# Reviewer assessment of the attached nine-finding architecture audit

2026-10-04. Source checked personally. This is a review and bounded work order, not a claim of implementation. Preserve unrelated dirty changes; no deploy/commit or destructive remote maintenance.

## Confirmed and corrected findings
1. WorkspaceActor production wiring: rg over apps/worker/src shows only namespace Env binding, not any namespace invocation. Queue and cron dispatch D1 directly; the DO is exercised by tests. This is topology/documentation drift, not proof that fencing is broken. Resolve with 014 transport ownership and invocation budget.
2. Guard storage: acceptance_guards, ledger_guards and lifecycle_guards receive UUID-keyed successful assertions with no discovered cleanup. Storage growth is real. Preserve scalar predicate + NOT NULL/CHECK failure inside the same atomic batch. A zero-row UPDATE or INSERT OR IGNORE cannot replace assertion. Evaluate one bounded reusable assertion row per scope with every invocation rechecking the predicate; legacy-row cleanup remains bounded and separately scoped. No new permanent row per operation.
3. Ledger cost is worse than load-all: executor.ts:579 loads all projections, then :854 entities, :999 fields, :1040 tasks, :1082 drafts unconditionally upsert every projected object. Memory loops also need inspection. Editing one item can rewrite unrelated projections. First record D1 metadata and exact SQL footprint for one command in a workspace with many unrelated records; then changed-only persistence while preserving current reducer and transaction contracts. Compare persisted values, not just Map/object identity, because reducers can shallow-copy or mutate. Targeted loading is a separate step after write footprint is bounded.
4. Context assembly: context.ts:238 loads all names and :244 queries active notes per matched entity. Use bounded workspace-scoped retrieval and batch relevant entity memory; preserve acting-member scope, suppression semantics and deterministic ranking. Do not impose an arbitrary LIMIT that silently makes entities undiscoverable. Exact timings/OOM assertions in the attachment are unmeasured.
5. Telegram wake: routes/inbound.ts accepts and returns without dispatch hint. Add immediate post-commit wake for dispatchable accepted/replayed durable work, not for linked/ignored/unrouted/unsupported/confirmation-required input. Queue failure must not turn successful acceptance into input loss. Test production webhook -> queue hint -> dispatched reply with synthetic provider, duplicate update and failure.
6. Workspace-wide turn lease is confirmed and was intentional. It blocks unrelated teammates during inference. This needs a separate deliberate concurrency design; do not replace the lease field with a chat field blindly. Run/step claims, fencing, scoped context, ledger revision conflicts, Undo, stop and stale-holder behavior all depend on it. Product outcome: independent chats can respond concurrently, while conflicting shared writes remain validated and atomic.
7. Healthy waiting_for_input workspaces are discovered every cron tick. Remove healthy parked work from routine discovery while preserving queued orphan/running expired/sending/cancelled recovery. Current zero-write test shows no healthy parked lease acquisition and zero changed rows; the attachment overstates that behavior as write thrashing. Prove reactive answer wake and crash recovery before changing selector.
8. Session validity expires already; physical expired rows and completed outbox retention are separate missing maintenance policies. Indexes do not automatically degrade just because history grows. Any retention must distinguish durable evidence, dedupe keys, retry recovery, pending/sending/outcome_unknown and terminal rows. Do not automatically delete everything delivered after an invented 7-day deadline. Preview growth is primarily corrected by 014, not periodic deletion.
9. Generic claim that filtering reverted events makes replay nondeterministic is rejected. rebuild.ts filters by explicit append-only revert events and committed sequence; commands/undo.ts:86 checks dependencies and :208 rejects unsafe undo. Existing tests UN-02 preserve teammate edits and UN-03 reject dependent-task undo. Point-in-time replay can use the event prefix. Add tests for uncovered actual dependencies if reproduced, but no generic compensating-inverse rewrite.
